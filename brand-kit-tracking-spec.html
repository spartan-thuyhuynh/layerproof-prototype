Brand Kit — Analytics Tracking Spec

Defines the questions we want to answer, the metrics that answer them, and the events that feed those metrics. Structured for developer implementation — one event card per event, with typed properties.

0

Feature Overview

Brand Kit is a net-new feature. Before it launched, users could only pick from system themes (8 pre-built) or standalone themes (user-created, no brand context). Brand Kit lets users define a brand identity once and generate consistent, on-brand themes from it. This document tracks whether that investment is paying off.

What's in a Brand Kit

A kit has 7 fixed sections (+ Brand Themes) and can have unlimited custom sections. Each section is independently editable and contributes to the kit's completeness score.

Overview
Brand name, tagline, color swatch, logo text. The identity card — the first thing users fill in during onboarding.
Colors
Named color palettes with hex swatches. Users build a palette library that feeds into theme generation.
Typography
Display and body font family + weight. Sets the typographic personality used in generated content.
Logos
Logo variants (light, dark, icon). Includes clear-color rules and minimum size guidance.
Imagery
Visual style description, mood tags, dos & don'ts. Can be rewritten by AI from the existing tags.
Brand Voice
Tone attributes, word lists, density setting, and a 4-axis voice spectrum (formality, humor, respect, enthusiasm).
Brand Themes
AI-generated prompt sets created from the kit. Each theme carries full brand context and is selectable in the content create flow.
Brand Guidelines
Structured brand documentation generated from the kit. Exportable as PDF or shareable link.
Themes

Themes are reusable prompt sets generated from the brand kit. They are the bridge between the brand definition and content creation — selecting a brand theme in the create flow is the primary conversion event.

System themes
8 pre-built themes. Available to everyone. No brand context. This was the only option before Brand Kit.
Standalone themes
User-created prompt sets, not tied to any kit. Custom but stateless — don't carry brand identity.
Brand themes ← new
Generated from the kit via AI chat (NewThemeModal). Carry full brand context. This is the target outcome we're measuring.
Main User Journeys to Track

The focus is adoption and behavior — how many users create and apply a kit, and whether that translates into using brand themes in content. Kit quality (section completeness, imagery accuracy, voice calibration) is out of scope for v1 tracking.

Journey 1 — Kit Creation via Onboarding
User reaches the brand kit step (Step 4) during onboarding → skips or completes setup → kit is auto-generated.
Track: completion rate vs skip rate. Does completing onboarding setup lead to higher kit adoption downstream?
Journey 2 — Kit Creation via Brand Kit Feature
User navigates to the Brand Kit feature post-onboarding → creates a new kit manually → edits sections → applies the kit.
Track: how many users discover and create a kit outside of onboarding? What sections do they fill in?
Journey 3 — AI Theme Generation
User enters the theme builder → submits a prompt → saves a generated theme.
Track: adoption rate (how many kit owners generate a theme), and prompt behavior (first submit vs iterate).
Journey 4 — Brand Theme in Content Creation
User selects a theme in the content creation flow. Theme source is "brand", "system", or "standalone". Kit adoption is measured here — if a user created a kit and selects a brand theme, the kit is considered in use.
Track: share of brand theme selections vs system/standalone. This is the primary outcome — everything else is funnel leading here.

How Tracking Works

Everything in this spec flows in one direction: from a product question down to raw data. Understanding this chain means anyone can trace why any given event exists — and know which events to ignore when answering a specific question.

① Questions
Start with what we actually want to know. Every question maps to a product hypothesis.
"Are users who apply a brand kit creating more content?"
② Metrics
A metric is a number that answers the question. It has a clear formula and a threshold for "success".
Content Volume by Theme Source — compare brand vs system/standalone users
③ Events
Events are the raw signals that feed the metric. Each has a name, a trigger (user action), and typed properties.
content_theme_selected with theme_source: "brand"
④ Insight
PostHog aggregates events into the metric. The metric answers the question. We act on the answer.
Brand themes are selected 40% less often than system themes at day 30 → fix theme discovery in the create flow
Rules that follow from this chain
  • If an event doesn't feed at least one metric, don't add it — it's noise.
  • If a metric doesn't answer a question in section 1, don't track it — it has no decision attached to it.
  • Properties on an event exist to allow segmentation of the metric, not for logging convenience.
  • content_theme_selected with theme_source is the single most important event — it's where every funnel in this spec terminates.

Measurement Framework

Brand Kit is a net-new feature. Before it launched, users had only two options: system themes (pre-built, no customisation) and standalone themes (user-created, not tied to a brand). This framework defines how we compare Brand Kit against that baseline.

Cohort Definition
Control — Baseline
System & Standalone users
Users who create content using only system themes or standalone themes. This was the only path before Brand Kit launched.
Signal: content_theme_selected where theme_source ≠ "brand", never
Treatment — Brand Kit
Brand Kit adopters
Users who complete brand kit setup (onboarding or in-app) and use a brand theme at least once in content creation.
Signal: onboarding_brand_setup_completed or brand_kit_created + content_theme_selected (theme_source: "brand")
Partial Adopters
Kit created, not used
Users who set up a kit but continue using system/standalone themes in content. Track separately — they signal setup friction or low theme discoverability.
Signal: brand_kit_created but no content_theme_selected (theme_source: "brand")
Measurement Periods

Measured from each user's first Brand Kit exposure (onboarding Step 4 view, or first visit to the feature).

WindowPeriodWhat we measure
ActivationDay 0–7Brand setup completion rate, kit apply rate
EngagementDay 7–30First brand theme used in content, section edit depth
StickinessDay 30+Return edit rate, sustained brand theme usage vs switching back to system/standalone
Evaluation Criteria

Brand Kit is considered successful at 30 days post-launch if all primary criteria are met and no guardrails are breached. Thresholds are placeholders — calibrate against baseline data in the first two weeks.

Criterion Type Target Measured at
Brand Kit adopters create more content than system/standalone-only users Primary ≥ 20% higher content volume vs control cohort Day 30
Onboarding brand setup completion rate Primary ≥ 50% of users who reach Step 4 complete setup Day 30
Brand theme share of all content created Primary ≥ 30% of content_theme_selected events use theme_source: "brand" Day 30
Kit completion rate (≥ 4 sections edited) Secondary ≥ 40% of created kits Day 30
AI theme builder adoption among kit owners Secondary ≥ 25% of kits have at least one generated theme Day 30
Total content creation does not decline Guardrail Week-over-week content volume ≥ pre-launch baseline Weekly
System theme usage does not collapse Guardrail theme_source: "system" share remains ≥ 20% Day 14, Day 30
Re-evaluation trigger: If brand theme share stays below 15% at day 30, escalate immediately — this signals that users are not discovering the brand themes in the content creation flow, not that Brand Kit itself is failing.

Event Groups

Events are organised into 7 groups that map to distinct stages of the user journey. Each group has a single job — understanding that job tells you which events to query for any given question.

Onboarding
Fires during the Step 4 brand kit wizard. Captures whether the user enters the Brand Kit funnel at all, and whether they complete or skip setup.
4 events
Lifecycle
Fires when a kit is created, opened, applied, or deleted. The backbone of adoption tracking — kit apply rate lives here.
4 events
Navigation
Fires when the user moves between sections inside a kit, or adds a custom section. Shows which parts of the kit get attention.
2 events
Section Edits
One event per section type (Colors, Typography, Logos, Imagery, Tone). Fires when the user makes any change inside that section. Indicates "this section was touched" — not every individual field change.
5 events
Brand Guidelines
Fires when guidelines are created, edited, or exported. Measures whether users discover and use the guidelines authoring feature and whether they distribute the output.
3 events
Themes
Fires when brand themes (reusable prompt sets) are created, viewed, or deleted. Measures theme feature discoverability and usage independent of AI generation.
3 events
AI Generation
Fires throughout the theme builder chat and the imagery rewrite flow. Measures AI feature adoption, prompt behavior (suggested vs typed), and iteration depth before saving.
7 events
Content Creation
A single event — content_theme_selected — fired when the user picks a theme in the create flow. The theme_source property ("brand" | "system" | "standalone") is the primary dimension for every Brand Kit vs baseline comparison. This is where the entire funnel terminates.
1 event

Out of Scope (v1)

  • Tracking individual color hex values (noise, no actionable insight)
  • Field-level keystroke tracking
  • Kit export / guideline generation (feature is deferred in the codebase)
  • Logo download tracking
  • Content created with a brand kit applied (cross-feature, tracked in a separate content creation spec)
  • Per-user identity linking (rely on PostHog's anonymous → identified flow)
