Overview

This document describes the new LayerProof homepage (/dashboard) — its sections, the product thinking behind each design decision, and the problems each change solves. The homepage is the first screen a returning user lands on after onboarding. It must orient users quickly, surface the right creation entry points, and reflect the breadth of LayerProof as a platform — not just a single-product tool.

Image
Full homepage screenshot — annotated with section labels
—
Background & Motivation
⚠ User session replay and product analytics show a consistent drop-off pattern on the current homepage: users land on the screen, do not interact, navigate around and exit without starting a creation flow.

The data indicates users are not failing at a specific step — they are uncertain what to do next from the moment they arrive. The homepage does not communicate what the product does, what options are available, or where to start.

This redesign directly addresses that drop-off. Every section and decision in this document is driven by the goal of reducing confusion at the homepage and converting more landing sessions into active creation sessions.

—
Product Goals
1
Increase creation rate
Reduce the number of users who land on the homepage and exit without starting a project.
2
Reduce confusion at first view
Every section of the homepage should give the user a clear signal of what to do next, with no dead ends.
3
Communicate product scope
LayerProof offers Social Posts, Docs, Presentations, Design, Apps, and AI tools. The homepage must make all of these discoverable without overwhelming the user.
4
Introduce new features
The homepage is the primary in-product surface for announcing new capabilities (e.g. Brand Kit, Vellum).
—
Page Structure

The homepage is split into two persistent regions: the Sidebar (fixed left panel) and the Main Content Area (scrollable). Together they make up the full homepage experience.

Create dropdown & hover preview

Clicking "Create new design" opens a dropdown listing all six creation products. Hovering any item reveals a side preview panel with a stylised thumbnail, product description, and three feature bullets.

Image
Sidebar create dropdown — open state with hover preview panel visible
Problem
  • Without persistent navigation, users must return to the homepage to switch products or access brand settings.
  • A top navbar collapses product-level navigation into a single row that doesn't scale as the product surface grows.
Solution
  • Always visible across all authenticated pages — stable orientation anchor regardless of current page.
  • "Create new design" is the topmost interactive element, most prominent action at all times.
  • Hover preview collapses product discovery and navigation into a single interaction.
  • "NEW" badge on Brand Kit reinforces the homepage announcement chip.

Top of main content area

What it is

The primary creation zone of the homepage. Three stacked elements that together answer the question a dropped-off user couldn't answer on their own: what can I make, and where do I start?

A large typographic headline — "What do you want to create today?" — paired with an animated announcement chip. The chip shows "New" and a rolling label for the latest feature launch (currently Brand Kit), with an arrow indicating it is tappable.

Problem
  • No clear starting point — product names don't show what users can actually accomplish.
  • Single creation path — missing the CTA left users with nowhere to go.
Solution
  • Headline phrased as a prompt, not a greeting — frames the page as an action surface.
  • Use-case language and real output thumbnails on cards.
  • Cards and pills ordered by creation frequency from user data.
  • Three entry points, each matched to a different user mindset.
◆ Future: Personalised cards — In a later iteration, cards and pills will be tailored per user based on their last project creation and most-used product types. Current version uses global usage frequency. Out of scope for this version.

New Sub-Product Banner
Below the creation zone

What it is

A full-width promotional banner that highlights the most recently launched sub-product. The banner is a reusable slot — not hardwired to any single product. Its content (background image, product chip, name, tagline, accent colours) is updated each time a new sub-product ships.

Default state: background image with gradient overlay, decorative colour orbs, product chip, name, and tagline. Hover state: background blurs, title fades, and two action buttons appear — "Try it" and "Read release note."

★ Current occupant: Vellum (AI-powered image generation under Space). Used here as the reference example.
Image
Sub-product banner — default (resting) state, current featured product visible
Image
Sub-product banner — hover state with action buttons visible
Problem
  • New sub-products go unnoticed when only announced in a changelog or tooltip.
  • No homepage surface promotes a launch with enough visual weight without intercepting high-intent users.
Solution
  • Generic promotional slot — updated with each launch or removed when nothing to promote.
  • Positioned after creation zone so high-intent users are not intercepted.
  • Hover-to-reveal keeps default state clean; actions surface on intent.
  • Colour orbs themed to the featured product's accent colours.

Recent Projects
Below the sub-product banner

What it is

A section titled "Pick up where you left off" showing a single row of four project cards. Each card contains a colour-coded thumbnail with a product icon, workspace name, project title, content type badge, and a last-viewed or last-edited timestamp. A "View All" link navigates to the all-projects page.

✦ Empty state: When a user has no projects, hide this section entirely.
Image
Recent projects row — four cards visible
Image
Recent project card — annotated with field labels
Problem
  • No fast path to in-progress work — users had to navigate to a projects list and search manually.
  • Breaks creative momentum on return visits.
Solution
  • 4 cards covers the most common return patterns without creating a long list.
  • Colour-coded content type badges for visual scan before reading titles.
  • Workspace name above title helps users with multiple workspaces.
  • "View All" is secondary — present but not competing with creation actions.
⚠ Known issue: Workspace names currently render as raw ISO timestamps (e.g. Workspace 2026-06-05T07:40:25Z). Must be replaced with human-readable names before ship.
5
Community Section
Bottom of homepage, below Recent Projects

What it is

A section titled "Explore community" showing a 12-card grid (3 rows) of publicly shared projects from other LayerProof users across all project types. Two inline filter dropdowns control language (English, Spanish, French) and sort order (Votes, Recent, Popular). A "View All" link navigates to the full community view.

Image
Community section — header with filters and card grid
Problem
  • No social signal showing what others are building — users can't assess output quality before committing.
  • No cross-pollination of ideas between workspaces.
Solution
  • Social proof before a user invests time creating their own project.
  • 12 cards (3 rows) keeps the section from dominating; primary action is still "create".
  • Language and sort filters surfaced inline — no navigation required.
⚠ Note: Community data is currently mocked. Integration with a real feed endpoint is required before production.

Out of Scope
This version
  • Global search / project search bar
  • Notifications feed
  • Personalised feature cards — tailoring cards and pills per user based on last project creation and most-used product types. Current version uses global usage frequency. Personalisation is the planned next iteration.
  • Empty state when the user has no recent projects
  • Empty state when the community feed returns no results
